## Supabase content flow

Content now follows this path:

`React Query / frontend -> /api/content/* -> Next.js API -> Supabase PostgreSQL tables`

1. Run `supabase/migrations/20260810000000_create_content_tables.sql` in the Supabase SQL editor.
   Then run `supabase/migrations/20260811000000_create_profiles.sql` to create the public user
   profile table and synchronize existing/future Supabase Auth users.
2. Use the `.env` generated by the connected Vercel-Supabase integration. The application reads
   `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, and `SUPABASE_SECRET_KEY` directly.
3. Start the app with `yarn dev`.

The service role key is server-only. Frontend code must use `/api/content/*` and must never access
Supabase directly.

## Admin login

Authentication follows this path:

`Email/Google login -> Supabase Auth -> HttpOnly cookies -> role guard`

Roles are stored only in Supabase `app_metadata`:

- `user`: default for Google signups; sees the pending-approval page and cannot enter Admin UI.
- `admin`: can use Admin content screens.
- `super_admin`: can use Admin screens and `/dashboard/users` to manage users.

Bootstrap the first Super Admin in Supabase Authentication by setting
`app_metadata.role = "super_admin"`. Do not put roles in `user_metadata`, because users can modify
that metadata themselves.

Google login uses Google Identity Services directly in popup mode. Set
`NEXT_PUBLIC_GOOGLE_CLIENT_ID` to the Web Application Client ID, and use that same Client ID in the
Supabase Google provider so the Google ID token can be exchanged for a Supabase session. Configure
`http://localhost:3300` and the production origin under Google Authorized JavaScript origins.
Popup mode does not use an application redirect URI.
